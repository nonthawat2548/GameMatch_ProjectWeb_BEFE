# เกณฑ์ Term Project BE–FE — อ้างอิงประกาศและภาพของอาจารย์

แหล่งอ้างอิง: ข้อความประกาศและภาพเกณฑ์ที่ผู้ใช้ส่งในวันที่ 10 พฤศจิกายน 2569 เกณฑ์นี้ใช้ตรวจหลักฐาน ไม่ใช่การรับรองว่าโปรเจกต์ได้คะแนนเต็มแล้ว

## ข้อกำหนดของงาน

- ทำ Web Application ที่สนใจ โดยห้ามทำเว็บหนังเหมือนที่เรียน GameMatch จึงใช้ข้อมูลเกมและฟังก์ชันแนะนำเกมตามความชอบ
- มี Guest, Member และ Admin พร้อมฟังก์ชันหลักที่ใช้งานได้ครบกระบวนการ
- ใช้ Tech Stack และวิธีที่เรียนเท่านั้น: React + Fetch API, Go และ PostgreSQL ตามตัวอย่างวิชา
- Frontend อยู่ Vercel; Backend อยู่ Render แบบเชื่อม Repo; Database อยู่ Supabase
- MovieHub เป็นตัวอย่างโครงและวิธีเขียน ไม่ใช่หัวข้อหรือข้อมูลที่นำมาส่งแทน GameMatch

## ส่วนที่ 2 การอธิบายผ่านคลิป — 7 คะแนน

| หัวข้อ | เต็ม | ระดับกลาง | เริ่มต้น / ไม่มีหลักฐาน |
|---|---|---|---|
| สาธิตระบบจริง (ทีม) — 2 | 2: รันระบบ Deploy จริง เห็นกระบวนการและผลลัพธ์ครบ | 1: สาธิตได้บางส่วน | 0.5: เห็นเพียงหน้าจอ / 0: ไม่สาธิต |
| โค้ดและเส้นทางข้อมูล (รายบุคคล) — 3 | 3: ชี้โค้ดจริง อธิบายรับข้อมูล → API → ผลลัพธ์ได้ถูกต้อง | 2: เข้าใจเส้นทางหลัก แต่รายละเอียดไม่ครบ | 1: บรรยายโค้ดแต่เชื่อมโยงไม่ได้ / 0: ไม่อธิบาย |
| เหตุผลและการแก้ปัญหา (รายบุคคล) — 2 | 2: อธิบายเหตุผล มีปัญหาและหลักฐานวิธีแก้จากงานจริง | 1: อธิบายได้ แต่หลักฐานไม่ครบ | 0.5: กล่าวกว้าง ๆ / 0: ไม่แสดงความเข้าใจ |

คะแนนแต่ละคน = ผลงานกลุ่ม 13 + สาธิตทีม 2 + อธิบายรายบุคคล 5 = 20

## ข้อกำหนดทีมและคลิป

1. ทีมละ 2 คน บางทีมมี 3 คน
2. คลิปไม่เกิน 15 นาทีต่อทีม ทุกขนาดทีม
3. ทุกคนต้องอธิบายโค้ดส่วนที่ตนรับผิดชอบ พร้อมระบุชื่อ
4. แบ่งเวลาให้เหมาะกับจำนวนสมาชิก
5. ประเมินความเข้าใจและหลักฐาน ไม่ได้ให้คะแนนความสวยของคลิป

ดูบทซ้อมและการแบ่งเวลา 14:30 นาทีใน `docs/DEMO.md`

## หลักฐานของ GameMatch ที่ยังต้องแยกให้ชัด

| รายการ | สถานะปัจจุบัน |
|---|---|
| React UI, state/effect/context, fetch, Router, tests/assertions, production build | มีผลตรวจในเครื่อง ดู `docs/VALIDATION.md` และ `docs/evidence/` |
| Guest ดูเกม/Quiz, Member Favorites/Preference/Profile, Admin CRUD | React tests และ headless Chromium desktop/mobile ผ่านโดยจำลอง API; ยังไม่ใช่ผลระบบ Deploy จริง |
| Go → Supabase, persistence, ownership สองบัญชี, Backend 401/403, RAWG rollback | ผ่าน integration tests กับ Supabase จริงและ headless React → Go → DB ในเครื่อง; upstream RAWG ในเทส rollback เป็น fixture ยังไม่มี key นำเข้าจริง |
| Vercel + Render เชื่อม Repo + Supabase พร้อม URLs | Deploy และตรวจเส้นทางจริงผ่านแล้ว ดู docs/DEPLOYMENT.md และ evidence/cloud-browser; ข้อมูลเริ่มต้นยังเป็น Demo ไม่ใช่ RAWG จริง |
| คลิปแต่ละคนและหลักฐานปัญหาที่ตนแก้จริง | มีคู่มือซ้อม ยังต้องให้สมาชิกทำความเข้าใจและบันทึกเอง |

การปรับหน้าตาช่วยให้งานใช้ง่าย แต่ไม่ทดแทนหลักฐาน Fetch → Go → DB, สิทธิ์ Backend, การ Deploy และการอธิบายรายบุคคล
